# 2026-11-05 최종 점검 현황과 남은 작업

기준일: 2026-11-05, 한국 시간. 최신 사용자 확인을 반영했다.

**GUI 개별 점검은 완료됐다. 남은 작업은 GPS 검사 → IMU 검사 → 전체 통합 검증이다.**

GUI 완료는 사용자의 최종 확인에 근거한다. 아래 GPS·IMU·통합 항목은 앞으로 수행할 검사이며 완료 결과로 표시하지 않는다.

## 1. 현재 상태

| 구분 | 상태 | 다음 행동 |
| --- | --- | --- |
| GUI·라이다 화면 | 완료, 사용자 확인 | 통합 운용 중 표시·응답 유지 확인 |
| GPS 개별 검사 | 남음 | 실제 수신·위치·수신 상실/복구 확인 |
| IMU 개별 검사 | 남음 | 실제 포트·출력 설정·자세·가속도·상실/복구 확인 |
| 전체 통합 검증 | 남음 | 모든 센서·안전 기능·통신·전원·재부팅 함께 확인 |

완료한 GUI를 별도 수정 작업으로 다시 열지 않는다. 통합 단계에서는 다른 기능을 함께 켰을 때 기존 GUI가 정상 유지되는지 확인한다.

## 2. 완료한 GUI·라이다 작업

- 실제 라즈베리 화면에서 가로 GUI를 사용하고 양쪽 점군이 표시되는 것을 확인했다.
- 정면 3D, 작은 점, 고정 기준점·눈금, 1/5/10cm 확대와 큰 시계 구성을 적용했다.
- 두 D2를 좌 채널 0·우 채널 1로 요청하고, 좌우 고정 장치 이름으로 실행했다.
- ROS Humble 점군 자료형 오류, Pi 수신 주소, 젯슨 전송 주소 끝 물결표 문제를 해결했다.
- 사용자가 GUI 점검 전체가 끝났다고 최종 확인했다. 세부 해상도·오차·지연의 별도 계측 수치는 이 기록에서 새로 주장하지 않는다.

과거 증상·원인·조치·근거는 [트러블슈팅 26개 사례](troubleshooting_history_20261105.md)에 보관했다.

## 3. 다음 검사 1: GPS

### 확인할 항목

- [ ] Pi에 연결된 실제 GPS 장치·Linux 포트·통신 속도를 확인한다. Windows COM 번호를 그대로 사용하지 않는다.
- [ ] 실제 센서 메시지가 수신·파싱되고 위치 정보가 갱신되는지 확인한다. 모의 위치나 PC 위치 시험과 구분한다.
- [ ] 수신 상태와 fix를 확인하고, 표시 위치를 실제 시험 장소와 비교한다. 위성 수·정밀도 지표는 장치가 제공하는 값을 함께 기록한다.
- [ ] 실내 등 fix가 어려운 조건과 유효한 위치를 얻은 조건을 구분한다. RTK를 사용하는 경우에만 해당 보정 수신·상태를 추가 확인한다.
- [ ] GPS 수신을 중단·복구했을 때 상태가 올바르게 바뀌는지 확인한다. 현재 유효 위치와 마지막으로 알려진 위치를 혼동하지 않아야 한다.

### 통과 판정

실제 GPS로부터 신선한 위치가 들어오고, 수신 불가·복구가 구분되어야 한다. 시험 조건과 실제 위치 비교 결과를 기록한다. 오차 목표나 RTK 성능을 측정 없이 확정하지 않는다.

## 4. 다음 검사 2: IMU

### 확인할 항목

- [ ] 실제 IMU와 수신기의 모델, Pi 포트, 통신 속도, 유선/무선 프로토콜을 확인한다.
- [ ] roll·pitch·yaw, 각속도·가속도 필드가 올바른 순서와 단위로 들어오는지 확인한다. 무선 구성이라면 해당 채널·센서 ID의 샘플인지 확인한다.
- [ ] 정지 상태 가속도 크기가 약 1g인지 확인하고 센서 장착 방향·오프셋을 기록한다.
- [ ] 앞뒤·좌우 기울임과 복귀에서 축·부호·각도 변화가 실제 움직임과 맞는지 확인한다.
- [ ] 실제 측정범위(FSR)와 설정을 확인한다. 정지 1g 확인만으로 충격 측정범위까지 검증됐다고 보지 않는다.
- [ ] 연결 중단·재연결에서 오래된 값이 정상값으로 유지되지 않는지, 유효 샘플이 다시 들어오는지 확인한다.

### 통과 판정

실제 IMU의 신선한 자세·가속도 데이터가 들어오고 장착 방향·단위·범위·연결 상태가 확인되어야 한다. 전도 판정 시험은 다음 통합 단계에서 수행한다.

외부 작업본의 무선 IMU 변경은 기본 통신 설정이 main과 다르다. [게시 대상 점검](publication_audit_20261105.md)을 참고해 실제 장치 설정에 맞는 버전을 선택한다. 검사 전에 무조건 921600bps·wireless로 바꾸지 않는다.

## 5. 마지막 단계: 전체 통합 검증

GPS와 IMU 개별 검사 후 다음 항목을 같은 실제 장치 구성에서 검증한다.

### 센서·화면 동시 운용

- [ ] 두 라이다·GPS·IMU·안전 감시·GUI를 함께 실행한다.
- [ ] 점군과 센서 상태가 갱신되고, 화면·터치·시계·버튼 응답이 정상 유지되는지 확인한다.
- [ ] 거리 입력을 사용하는 구성에서는 실제 거리 입력·경고 경로를 확인한다. 3D 화면 성공으로 거리 경고 성공을 대신하지 않는다.
- [ ] GUI를 종료·재실행해도 안전 감시가 독립적으로 유지되는지 확인한다.

### 안전 기능과 시험 알림

- [ ] 사람이 의지하지 않는 시험 구성에서 정상 움직임·기울어짐·충격·전도 후보를 구분해 검사한다.
- [ ] 사용자 확인 팝업, 예/아니오·취소, 사고 확정, 사고 후 감시 재개의 전환을 확인한다.
- [ ] 합의한 시험 채널에서 SOS·보호자 알림 경로를 확인한다. 시험 메시지임을 표시하고 실제 사고로 처리하지 않는다.
- [ ] 큐 접수, 전송 중, 서버 접수, 실패와 실제 시험 채널 수신을 구분해 기록한다. 서버 접수만으로 보호자가 읽었다고 보지 않는다.

### 통신·전원·복구

- [ ] 최종 운용 네트워크를 확정한다. 요청했던 랜선 직결·고정 IP가 필요하면 실제 인터페이스·현재 SSH 경로를 확인한 뒤 적용하고 유선 경로의 센서 수신까지 검사한다.
- [ ] 한쪽 라이다, 네트워크, 송신 프로그램을 각각 중단·복구해 오래된 표시 제거와 정상 수신 복구를 확인한다.
- [ ] 센서·프로그램 재시작 후 새 세션의 데이터가 다시 수신되는지 확인한다.
- [ ] 실제 전원 구성에서 자동 실행·재부팅 후 전체 운용 상태를 확인한다. GUI 단독 자동 실행 코드 게시와 전체 장치 자동 실행 검증은 구분한다.
- [ ] 기존 계획인 30분 연속 동시 운용을 수행하고 중단·지연·전원 문제·복구 여부를 기록한다.

랜선 고정 IP의 계획 주소는 젯슨 192.168.10.1/24, Pi 192.168.10.2/24다. 이 대화에서는 해당 전환의 적용·검증 완료 보고가 없으므로 통합 항목에 포함했다. 현재 실제 주소와 다르면 확인 후 설정한다.

## 6. 최종 완료 조건과 결과 기록

**GPS 개별 검사 통과 + IMU 개별 검사 통과 + 전체 통합 검증 통과**가 최종 완료 조건이다.

각 검사에서 사용 코드 버전, 실제 장치·포트·통신 설정, 시험 조건, 정상/실패/복구 결과를 기록한다. 실제 위치·인증정보·장치별 설정은 공개 Git 기록에 불필요하게 포함하지 않는다.

```text
검사일 / 담당자:
코드 버전:
장치·포트·통신 설정:
GPS: 미실시 / 통과 / 보완 필요
IMU: 미실시 / 통과 / 보완 필요
통합: 미실시 / 통과 / 보완 필요
중단·재연결·재부팅 결과:
30분 동시 운용 결과:
시험 알림 실제 수신 확인:
남은 문제와 재검사 결과:
```
