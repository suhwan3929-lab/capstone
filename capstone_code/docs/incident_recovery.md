## 동작

사고 확정 전에는 기존의 움직임·자세 복귀 및 사용자 취소 흐름을 유지한다.
사고가 확정되고 알림을 처리한 뒤에는 `사고 확정 · 조치 확인 대기` 상태를 유지한다.
이때 대시보드 오른쪽의 SOS 버튼 위에 **조치 완료 · 감시 재개** 버튼이 표시된다.

상황을 확인하고 조치를 마친 사용자가 버튼을 누른 뒤 확인창에서 확인하면
기존 `CMD_RESET` 명령을 안전 감시 프로세스로 보낸다. 화면이 자체적으로 사고를 해제하지 않는다.
안전 감시 프로세스가 정상 상태를 보내면 버튼이 사라지고 정상 감시 표시로 돌아간다.
재개 직후 기존 5초 쿨다운을 유지하며, 이후 새 사고를 다시 감지한다.

보행기 자세가 정상으로 돌아온 것만으로 확정된 사고를 자동 해제하지 않는다.
기존 사고 알림과 CSV 기록을 지우거나 취소하지 않고 미전송 사고 알림의 재시도도 유지한다.
연결 끊김 및 알림 처리 중에는 버튼을 비활성화하고, 확인창을 닫는 동안 연결/상태가 바뀌면 명령을 보내지 않는다.
감시 재개 요청의 응답이 2초 안에 없으면 다시 요청할 수 있다.

기존 코드의 `TIPOVER_REPORTED` / `신고 완료`는 알림 큐에 접수된 내부 상태이며
보호자가 실제 수신했음을 뜻하지 않는다. GUI는 이를 `사고 확정 · 조치 확인 대기`로 표시한다.

## Pi에 적용

Windows PowerShell에서 두 파일을 전송한다.

```powershell
scp "D:\26-1\26-2 capstone\capstone_code\ui.py" yu@192.168.0.173:/tmp/walker_ui.py
scp "D:\26-1\26-2 capstone\capstone_code\states.py" yu@192.168.0.173:/tmp/walker_states.py
```

Pi에서 현재 run_dev.py 실행 터미널의 Ctrl+C로 프로그램을 종료한 뒤 백업하고 적용한다.

```bash
cd /opt/walker/capstone_code
sudo cp --update=none ui.py ui.py.before-recovery
sudo cp --update=none states.py states.py.before-recovery
sudo install -m 644 /tmp/walker_ui.py ui.py
sudo install -m 644 /tmp/walker_states.py states.py
```

현재 사용 중인 실제 GPS·IMU GUI를 다시 실행한다. config_local.py의 센서 설정은 유지한다.
현재 LiDAR 단독 제외 시험 설정은 `LIDAR_SOURCE = "none"`이다.

```bash
WALKER_SIM=0 /opt/walker/venv/bin/python run_dev.py --no-alert
```

## 사고 확정·복귀 시험

실제 센서를 충격으로 시험할 필요 없이, 정상 센서 실행을 종료하고 다음 시뮬레이션으로 확인한다.
기존 실제 프로그램과 시뮬레이션을 동시에 실행하지 않는다.

```bash
/opt/walker/venv/bin/python run_dev.py --sim --scenario tipover_front --no-alert
```

사고 확인 팝업이 나타나면 `예 (신고하기)`로 확정하거나 무응답 타이머 종료를 기다린다.
확정 후 버튼이 표시되는지 확인하고, 조치 완료 확인창에서 취소하면 사고 상태가 유지되는지 확인한다.
다시 버튼을 눌러 확인하면 정상 상태로 돌아가는지 확인한다.
시뮬레이션 센서는 계속 넘어져 있는 값을 낼 수 있으므로 감시 재개가 센서 자세를 바꾸지는 않는다.

보호자 알림 계정이 설정돼 있으면 이 시뮬레이션도 사고 알림을 전송한다.
`--no-alert`는 부저·LED 등 현장 출력만 끄고 보호자 알림 전송을 끄는 옵션이 아니다.
전송 계정이 있는 환경에서는 해당 시험용 수신 대상을 먼저 준비한다.
