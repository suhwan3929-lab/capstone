# `notifier.py`

> **한 줄:** 보호자에게 Discord Webhook으로 알림을 보낸다. 2단 전송 + 재시도 + 디스크 스풀.
> **계층:** 알림 (안전 필수) | **의존:** `config`, `schema`, `states`, `requests`(선택)

---

## 무엇을 하는가

```python
is_configured()                          # 웹훅 URL이 진짜로 유효한가
start(log_callback)                      # 워커 스레드 + 스풀 복구
send_preliminary(imu, gps, age)          # 충격 감지 즉시 — 예비 알림
send_confirmed(imu, gps, age, peak_g)    # 전도 확정 — 본 신고
send_cancelled(reason)                   # 해제 알림
pending()                                # 미전송 건수
```

## 설계 포인트

### 2단 전송 — 골든타임

**충격을 감지한 즉시 예비 알림을 보낸다.** 판정에는 최대 20초가 걸리는데,
그동안 보호자가 아무것도 모르고 있으면 골든타임을 그만큼 잃는다.
판정이 끝나면 확정 또는 해제 알림이 뒤따른다.

지도 이미지는 **텍스트 전송 이후에** 별도로 첨부한다.
리팩터링 전에는 지도를 먼저 받느라 신고가 최대 10초 밀렸다.

### 측위 품질을 함께 보낸다

좌표만 주지 않고 **측위 품질(단독/DGPS/RTK 고정/RTK 부동), 위성 수, HDOP,
좌표 신선도**를 같이 보낸다. 보호자에게 "오차 ±2 cm"와 "오차 ±5 m"는 완전히 다른 정보다.

### 디스크 스풀 — 사고 알림은 사라지면 안 된다

LTE가 끊긴 순간에 사고가 나고 프로세스가 죽으면, 메모리 큐만 있는 구조에서는
**그 알림이 영영 통보되지 않는다.** 사고 알림은 다시 만들 수 없는 정보다.

확정 알림은 전송 전에 `logs/pending_alerts.jsonl` 에 `fsync` 로 기록되고,
전송 성공 시 제거된다. 다음 기동 때 남아 있으면 이어서 보내며,
메시지에 **"지연 발송"** 과 사고 발생 시각을 표시한다.

### URL 검증

```python
def is_configured():
    return url.startswith("https://discord.com/api/webhooks/") and len(url) > 50
```

리팩터링 전 코드는 `if not URL:` 이었는데, 플레이스홀더 문자열
`"https://discord.com/api/webhooks/..."` 가 truthy라 **가드가 절대 발동하지 않았다.**
미설정 상태에서 사고가 나면 경고 대신 잘못된 URL로 POST를 시도하고 실패 로그만 남겼다.

## 고칠 때 주의

- ⚠ **웹훅 URL을 로그에 절대 출력하지 말 것.** 예외 메시지에도 포함되지 않게
  `type(e).__name__` 만 찍는다. 유출되면 제3자가 실시간 위치를 수신할 수 있다.
- ⚠ **`send_*()` 는 큐에 넣기만 하고 즉시 반환한다.** 판정 루프를 멈추면 안 되기 때문이다.
  실제 전송은 워커 스레드가 한다.
- `requests` 가 없어도 import 에러로 죽지 않는다. 알림만 비활성화되고 판정은 계속 동작한다.
- 예비/해제 알림은 스풀에 남기지 않는다(`DURABLE_KINDS`). 시간이 지나면 가치가 없기 때문.

## 미해결

- 전송 실패가 계속되면 스풀이 누적된다. `NOTIFY_SPOOL_MAX` 로 상한을 두었으나
  오래된 항목 정리 정책은 아직 없다.
- Discord 외 채널(SMS 폴백 등)은 미구현. 계획서 리뷰 §4.2의 FMEA 항목.
