# `ui.py`

## 2026-11-04 7인치 가로 3D 배치 적용

- 기본 크기는 1024×600이며 좌우 3D 점군을 중앙에 크게 둔다. 1280×720에서도 확장한다.
- 상단 왼쪽에 제목·배터리를 두고 오른쪽 별도 영역에 30pt 굵은 흰색 시계를 표시한다.
  시간은 8자리 폭을 고정해 초 갱신 때 배치를 흔들지 않는다.
- 기본은 정면 3D이며 상단의 3D/2D·시점·점군 선택 버튼 줄은 숨긴다.
- 사용자에게는 `화면 확대`로 안내하고 `1cm · 5cm · 10cm`를 선택하게 한다. 설명은 `한 칸의 실제 거리`다.
  기본은 10cm이며 양쪽 화면을 함께 바꾼다. 한 칸의 화면 길이를 유지하므로 5cm는 기존 대비 2배,
  1cm는 10배 확대다. 버튼은 센서 범위·정확도·선택된 원본 점을 바꾸지 않는다.
- 두 LiDAR 카드의 하단 장애물 거리 행과 색상 설명을 숨겨 그 공간까지 3D 화면을 확장한다.
  1024×600 USB 시험에서 각 캔버스 높이는 223px에서 303px로 늘었고, 확대 선택 추가 후에는 295px다.
- 점 지름은 2px, 3축 모형은 제거했다. 선택한 눈금의 중심·배율은 점군과 무관하게 고정한다.
- 네 시점 모두 센서에서 점까지의 거리 색이다. 10cm 파랑, 20cm 청록, 35cm 초록,
  60cm 노랑, 1m 주황, 2m 분홍으로 고정 보간한다. 센서 자세나 측정 잡음을 보정하지 않는다.
- IMU·GPS·로그는 `센서 상세 보기`에 둔다. SOS와 사고 후 감시 재개는 두 화면에서 같은 위치다.
- 화면 전체 오버레이 대신 위험 배너 테두리를 점멸하여 조작 버튼을 가리지 않는다.
- 화면 해상도가 1024×600이면 자동 전체 화면으로 연다. 최소 지원 크기는 1024×600이다. F11은 전체 화면 전환,
  Esc는 상세 보기에서 복귀하거나 전체 화면을 해제한다.
  `WALKER_UI_FULLSCREEN=1/0`으로 자동 판단보다 우선해 지정할 수 있다.
- 3D 수신·좌표·2m/192점/10Hz 축약과 기존 안전 판정 경로는 변경하지 않는다.
- PC에서 실제 USB 라이다 두 대를 연결하는 [표시 전용 시험 도구](usb_3d_pc_test.md)도 제공한다.
  USB는 최대 9,600 유효 점 전체 선택·정면·10cm 확대를 기본으로 유지한다. Pi/Jetson UDP는 기존 192점이다.
  `화면 N/M점`으로 화면 안에 그린 점 수/선택된 점 수를 구분한다. 확대 화면 밖의 점은 잘릴 수 있다.

상위 작업 소스에 적용했으며 `.publish-capstone` 및 원격 GitHub는 이번 변경에 포함하지 않았다.

## 2026-11-04 상태 표시 수정

- IMU 또는 활성 LiDAR 연결에 문제가 있으면 상단에 `감시 일부 불가`를 표시한다.
  정상 수신 중인 반대쪽 LiDAR의 위험 경고도 함께 유지한다.
- 감시 연결이 끊기면 IMU 값·GPS 좌표·현재 위치 마커를 지우고 마지막 상태 수신 시각을 표시한다.
  GPS 자체가 무효이거나 좌표/측위가 없을 때도 현재 위치 마커를 제거한다.
- 화면 SOS는 모니터 연결 중에만 사용한다. 요청 후 처리 확인을 기다리는 2초 동안 중복 입력을 막고,
  확인되지 않으면 다시 요청할 수 있다. 이미 확정된 사고는 기존 조치 완료 경로를 따른다.
- 버튼 아래에서 확정 알림의 큐 접수, 전송 중, Discord 서버 접수, 실패, 설정 없음 상태를 구분한다.
  서버 접수는 보호자 열람 확인이 아니다. 구버전 모니터는 `전송 결과 확인 불가`로 표시한다.
- 새 상태 필드는 `SystemStatus` 최상위에 추가되어 구버전 수신기가 무시할 수 있다.
  상세 전송 결과를 보려면 Pi의 `ui.py`, `schema.py`, `status_link.py`, `notifier.py`,
  `safety_monitor.py`를 함께 갱신하고 모니터와 GUI를 재시작한다.

고정 IP와 자동 실행 설정을 보존하는 적용 순서는 [GUI 갱신 안내](gui_status_update.md)를 따른다.

## 무엇을 하는가

`safety_monitor` 가 UDP로 보내주는 `SystemStatus` 를 100 ms마다 폴링해 그린다.
사용자 버튼 입력(취소/확인/SOS)만 되돌려 보낸다.

**이 창을 닫아도, 멈춰도, 죽어도 전도 감지는 계속 동작한다.**

## 리팩터링에서 고친 것

| 문제 | 조치 |
| :--- | :--- |
| 판정·신고 로직이 GUI 안에 있었다 | 전부 `tipover_monitor` / `notifier` 로 이관 |

| 종료 처리 없음 | `WM_DELETE_WINDOW` 추가 |

### 오버레이 ↔ 팝업 충돌이 왜 중요했나

장애물에 부딪혀 넘어지면 **LiDAR 위험(깜박임)과 충격(팝업)이 동시에 발생한다.**
두 창 모두 `-topmost` 라 z-order가 보장되지 않아,
**사용자가 "아니오(취소)" 버튼을 못 누르면 오신고가 그대로 나간다.**

## 고칠 때 주의

- ⚠ **판정 로직을 여기에 절대 넣지 말 것.** 이 규칙이 깨지면 프로세스를 나눈 의미가 없다.
  "UI를 죽여도 안전 기능이 도는가"가 유일한 판정 기준이다.
- ⚠ **tkinter 위젯을 스레드에서 건드리지 말 것.** `StatusSubscriber` 는 별도 스레드에서
  받아 보관만 하고, 그리기는 메인 스레드의 `_refresh()` 가 폴링해서 한다.
- ⚠ 배터리를 로컬 sysfs에서 직접 읽지 말 것. 실기(BAT0 없음)에서 또 거짓말을 하게 된다.
- 팝업은 `WM_DELETE_WINDOW` 를 무시한다. X로 닫아 회피하지 못하게 하기 위함.

## 미해결

- `tkintermapview` 가 없으면 지도 영역만 비활성화되고 나머지는 정상 동작한다.
- 소형 터치스크린(800×480) 대응은 `minsize(1024, 600)` 로 부분적. 레이아웃 재검토 필요.

## LiDAR 윤곽 그림

각 카드의 오른쪽은 센서 기준으로 위에서 내려다본 그림이다. 위쪽이 센서 전방이고
왼쪽이 센서 좌측이다. 최대 4m 범위를 1m 간격으로 표시하며, 범위 밖 점 개수를 안내한다.
위험/경고 거리의 점은 기존 임계값에 따라 빨강/주황, 나머지는 초록으로 표시한다.
숫자는 기존 하위 퍼센타일 대표 거리이며 그림에서 가장 가까운 점과 조금 다를 수 있다.

Jetson 브리지는 기존 ROI에 들어온 LaserScan/PointCloud2 측정점에서 각도 구간별
가장 가까운 점을 골라 좌우 각각 최대 32개의 `[전방_m, 좌측_m]`를
선택 필드 `points_xy`로 보낸다. 3D 점군도 높이 필터 후 평면에 투영한다.
이는 축약된 현재 윤곽이며, 물체 종류를 인식하거나 누적 지도를 만드는 기능은 아니다.
각 센서 좌표를 사용하므로 보행기 전체 좌표로 합치려면 실제 장착 위치/방향 보정이 필요하다.

- 링크나 해당 센서가 끊기면 이전 점군을 즉시 지운다. 모니터 연결이 끊겨도 지운다.
- 정상 프레임의 빈 목록은 `이번 측정에 유효 점 없음`으로 표시한다.
- 점군 필드가 없는 구버전 브리지/시리얼 소스는 `거리만 수신 · 그림 데이터 없음`으로 표시한다.
  거리 하나로 가짜 주변 형태를 생성하지 않는다.
- 모의 실행에는 `모의 점군` 표시가 붙는다. `obstacle` 시나리오로 접근하는 윤곽을 볼 수 있다.
- 점군은 표시 전용이며 전도 FSM, 거리 경고, SOS 판정에는 사용하지 않는다.

실기에 적용하려면 Pi의 `schema.py`, `status_link.py`, `sensors/lidar_udp.py`, `ui.py`와
Jetson의 `lidar_bridge_node.py`를 함께 갱신한다. Jetson은 기존 ROS 작업공간에서
`colcon build --packages-select walker_lidar` 후 환경을 다시 읽고 브리지를 재시작해야 한다.
PC 소스 수정만으로 현재 Pi 화면/Jetson 프로세스가 바뀌지는 않는다.

센서/모니터 없이 카드만 확인하려면 `python tools/preview_lidar_ui.py`를 실행한다.
하단 버튼으로 점군, 링크 끊김, 센서 응답 없음, 거리만 수신, 빈 프레임 표시를 바꿀 수 있다.
이 도구는 네트워크나 알림 기능을 시작하지 않는다.

콜백, 점군 축약, 패킷 호환성, 링크 끊김 시 그림 제거 및 기존 안전 기능 테스트는 총 82개 통과했다.
