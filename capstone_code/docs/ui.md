## 무엇을 하는가

`safety_monitor` 가 UDP로 보내주는 `SystemStatus` 를 100 ms마다 폴링해 그린다.
사용자 버튼 입력(취소/확인/SOS)만 되돌려 보낸다.

**이 창을 닫아도, 멈춰도, 죽어도 전도 감지는 계속 동작한다.**

## 화면 구성

| 위젯 | 표시 |
| :--- | :--- |
| 헤더 | 시계, 배터리, RTK 보정 상태, 미전송 알림 수, 종합 상태 |
| `LidarCard` ×2 | 좌/우 최근접 거리, 등급 색상 |
| 단차 라벨 | 전방 단차 거리와 종류(내려가는/올라가는 턱) |
| `IMUCard` | 전도 판정 상태, roll/pitch/충격량 |
| `GPSCard` | 측위 품질(RTK 고정 등), 위성 수, HDOP, 지도 |
| `TerminalCard` | 시스템 로그 |
| SOS 버튼 | 화면에서도 긴급 호출 가능 |
| `FlashOverlay` | 위험 거리에서 화면 전체 깜박임 |

## 리팩터링에서 고친 것

| 문제 | 조치 |
| :--- | :--- |
| 판정·신고 로직이 GUI 안에 있었다 | 전부 `tipover_monitor` / `notifier` 로 이관 |
| 깜박임 오버레이가 확인 팝업을 가렸다 | **팝업이 뜨면 오버레이 정지** |
| 배터리가 항상 100%로 표시 | `safety_monitor` 가 보낸 값 사용, 없으면 "측정 안 됨" |
| 스레드에서 tkinter 호출 | 상태는 폴링으로만 읽는다 |
| 지도를 초당 10회 재중심 | 위치가 바뀐 경우에만, 최대 1 Hz |
| 종료 처리 없음 | `WM_DELETE_WINDOW` 추가 |

### 오버레이 ↔ 팝업 충돌이 왜 중요했나

장애물에 부딪혀 넘어지면 **LiDAR 위험(깜박임)과 충격(팝업)이 동시에 발생한다.**
두 창 모두 `-topmost` 라 z-order가 보장되지 않아,
**사용자가 "아니오(취소)" 버튼을 못 누르면 오신고가 그대로 나간다.**

## 고칠 때 주의

- ⚠ **판정 로직을 여기에 절대 넣지 말 것.** 이 규칙이 깨지면 프로세스를 나눈 의미가 없다.
  "UI를 죽여도 안전 기능이 도는가"가 유일한 판정 기준이다.
- ⚠ **tkinter 위젯을 스레드에서 건드리지 말 것.** `StatusSubscriber` 는 별도 스레드에서
  받아 보관만 하고, 그리기는 메인 스레드의 `_refresh()` 가 폴링해서 한다.
- ⚠ 배터리를 로컬 sysfs에서 직접 읽지 말 것. 실기(BAT0 없음)에서 또 거짓말을 하게 된다.
- 팝업은 `WM_DELETE_WINDOW` 를 무시한다. X로 닫아 회피하지 못하게 하기 위함.

## 미해결

- `tkintermapview` 가 없으면 지도 영역만 비활성화되고 나머지는 정상 동작한다.
- 소형 터치스크린(800×480) 대응은 `minsize(1024, 600)` 로 부분적. 레이아웃 재검토 필요.
