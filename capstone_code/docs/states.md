# `states.py`

> **한 줄:** 상태 문자열과 명령 코드의 단일 정의처(single source of truth).
> **계층:** 기반 | **의존:** 없음

---

## 무엇을 하는가

시스템 전체가 공유하는 문자열 상수를 정의한다.

| 그룹 | 상수 |
| :--- | :--- |
| 센서 연결 상태 | `CONN_WAITING`, `CONN_ERROR`, `CONN_OK`, `CONN_STALE` |
| 전도 판정 FSM | `TIPOVER_NORMAL`, `TIPOVER_STABILIZING`, `TIPOVER_CHECKING`, `TIPOVER_ASKING`, `TIPOVER_CONFIRMED`, `TIPOVER_REPORTED` |
| UI 표시 | `TIPOVER_DISPLAY` (상태 → 배지문구·색상 매핑) |
| 경고 등급 | `LEVEL_OK`, `LEVEL_WARN`, `LEVEL_DANGER` |
| 사용자 명령 | `CMD_USER_YES`, `CMD_USER_NO`, `CMD_RESET` |
| GNSS 품질 | `FIX_QUALITY_NAME`, `fix_quality_name(q)` |

## 왜 존재하는가 — 실제 버그에서 나왔다

이 파일은 장식이 아니다. **이것이 없어서 신고가 발송되지 않는 버그가 있었다.**

리팩터링 전 코드에서 `imu_sensor.py` 는 `"낙상 확정"` 을,
`main_controller.py` 는 `"사고 확정"` 을 각자 문자열 리터럴로 들고 비교했다.
두 문자열이 달라서 **센서가 스스로 사고를 확정한 경로에서는 디스코드 신고가 나가지 않았다.**
게다가 UI 매핑 테이블에도 그 상태 키가 없어 화면이 이전 상태로 멈춰 있었다.

양쪽이 이 모듈을 import 하면 그런 버그가 **구조적으로 불가능**해진다.

## 용어 — 중요

파일 최상단에 용어집 박스가 있다. 요지는:

- **측정량:** 보행기 프레임의 충격 가속도 + 자세각
- **판정 사건:** 보행기 전도(轉倒, walker tip-over) ← 시스템이 실제로 판정하는 것
- **관심 사건:** 보행 중 낙상 ← 알고 싶은 것
- 전도는 낙상의 **대리 지표(proxy)** 이며 완전히 일치하지 않는다

성능을 보고할 때 "낙상 탐지율"이 아니라 **"전도 탐지율"** 이라고 써야 한다.

## 고칠 때 주의

- **상태 문자열을 다른 파일에 직접 적지 말 것.** 반드시 여기서 import.
- 상태를 추가하면 **`TIPOVER_DISPLAY` 에도 반드시 항목을 추가**해야 한다.
  없으면 UI가 그 상태에서 갱신을 멈춘다(과거 버그와 동일한 증상).
- 최상단 용어집의 "낙상"은 **의도적으로 남긴 것**이다. 전도와 대비시키는 것이 목적이므로
  일괄 치환하지 말 것.
- 상태 문자열은 UDP로 JSON 직렬화되어 UI로 전달된다. 값을 바꾸면
  구버전 UI와 호환이 깨진다 — 두 프로세스를 함께 배포할 것.
