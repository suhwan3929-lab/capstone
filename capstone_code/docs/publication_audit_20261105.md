# 추가 코드·문서 게시 점검

점검일: 2026-11-05, 한국 시간. 외부 작업 폴더와 실제 Git 게시 체크아웃을 파일별로 비교했다.
비교 기준 main은 PR #3 병합 `65169cd`다. 미게시 항목은 코드가 없다는 뜻이 아니라 별도 개발 변경이 남아 있다는 뜻이다.

## 1. 기존 main에 반영된 실제 적용 코드

- GUI: 정면 3D, 작은 점, 고정 중심·눈금, 1/5/10cm 확대, 큰 시계와 점군 영역 확대.
- 두 D2: 채널 0/1 시작 요청, 최대 9,600 유효점의 v2 전송, 오래된 점 제거와 세션 재시작 복구.
- 상태 구분: 3D 표시와 거리·전도·SOS 경로 분리, 3D 수신 상태와 안전 상태의 독립 표시.
- ROS Humble 혼합 필드 오류: XYZ를 이름순으로 읽는 3D 노드·PointCloud2 거리 콜백 수정. PR #3.

다음 핵심 파일 10개는 외부 작업본과 기준 main이 줄바꿈 차이를 제외하고 같았다.

```text
ui.py
lidar_preview.py
lidar_preview_view.py
stream_order.py
jetson/lidar_bridge_node.py
jetson/lidar_preview_node.py
jetson/launch/walker_lidar.launch.py
tools/usb_lidar_3d.py

```

`codex/powerbank-discord-safety`의 `a76f30a`가 기준 main의 조상임도 확인했다.
그 작업이 main 이력에 포함돼 있다. 해당 브랜치 자체가 최신 main과 같다는 뜻은 아니다.

## 2. 이번 추가 게시 대상

- 기존 원격 접속 안내: 트러블슈팅 문서의 참조 파일을 함께 게시하고 최신 실기 기록 링크를 추가했다.
- 트러블슈팅 Markdown·HTML: 26개 문제의 원인·해결·확인 결과, 미확정 원인과 남은 실기 검증.
- `docs/images/troubleshooting_20261105/`: 근거 화면 5장. 인증 비밀번호가 보이는 화면은 제외했다.
- `tools/diagnose_usb_lidar_3d.py`: 기존 USB 시험 문서가 참조하던 동시 → USB1 단독 → 동시 원시 깊이 비교 도구. 포트별 스레드와 체크섬 상태로 비교 가능 여부를 검사한다.
- 진단 통계 검사 3개와 테스트 실행기 등록: 빈/단일 프레임, 알려진 거리 변화, 무효점으로 인한 가짜 점프 방지.
- 문서 색인과 이 게시 점검 기록.

이 도구는 개발·실물 시험용이며 소비자 GUI에 수신 진단 화면을 추가하지 않는다.
사용 전에 같은 USB를 읽는 GUI·드라이버를 종료한다. 실행하면 측정 시작/정지와 기본 채널 요청이 발생한다.
장치에 저장된 통신 속도·ID 변경은 수행하지 않는다.

## 3. 별도로 남긴 개발 변경

### 무선 IMU와 기본 설정

외부 `sensors/imu_sensor.py`, `config.py`, `config_local.py.example`, `tests/test_imu_sensor.py`, `docs/wireless_imu.md` 등에 변경이 있다.
무선 CH-ID 검사, 설정 응답 확인과 921600bps·wireless 기본값이 포함된다.

그대로 복사하면 기준 main의 115200bps 동작과 프로토콜 가정이 바뀐다.
현재 Pi의 실제 IMU 포트·프로토콜·보율은 아직 확인하지 않았으므로 이번 GUI 배포에 섞지 않았다.
기존 유선 사용자 호환성을 정한 뒤 드라이버·설정·시험·문서를 한 묶음으로 검증할 대상이다.

### Windows PC 위치·지도 포함 Discord 시험

외부 `tools/discord_test.py`, `tools/pc_location.py`, `tools/map_preview.py`, `tests/test_pc_location.py`에 별도 변경이 있다.
숨김 토큰 입력, Windows 위치 조회, 선택적 지도 이미지 첨부 기능이다.

이번 Pi 점군 표시 오류의 해결 코드와 구분해 남겼다. 부분 파일만으로 게시된 도구를 덮어쓰지 않았다.
별도 반영 시 관련 도구·시험·사용 설명을 함께 검증하고 실제 전송은 합의한 시험 채널에서 수행한다.
이번 점검에서는 실제 위치를 조회하거나 외부 메시지를 보내지 않았다.

### 배터리 설명과 기타 문서

외부 `battery.py` 차이는 실행 로직이 아닌 설명·주석 보정이다.
MAX17043의 ModelGauge 방식과 USB/PD 출력에서 내부 잔량을 직접 구할 수 없다는 설명 등이 있다.
`docs/battery.md`, `docs/power_meter_estimation.md` 등에는 별도 하드웨어 검토가 남아 있다.
잔량 통신 기능이 새로 구현되거나 실물에서 검증됐다는 뜻은 아니다.

외부 문서 색인·센서·시스템 설치 설명·과거 진행 기록도 일부 다르다.
기능별 검증과 함께 반영할 대상으로 분리했다. 게시 체크아웃에만 있는 루트 README나 과거 문서를 삭제하지 않았다.

### 점검 중 감지된 자동 실행 작업

공유 게시 폴더의 `systemd/install_autostart.py`, `systemd/README.md`, `tests/test_autostart.py`에 별도 변경이 생긴 것을 확인했다.
해당 변경을 덮어쓰거나 이 문서 PR에 섞지 않고, 기준 main에서 별도 작업공간을 만들어 검증했다.
이 기록은 그 자동 실행 변경이 실패했다거나 게시할 필요가 없다는 판정이 아니다. 해당 작업의 검증·게시 결과를 따로 확인한다.

## 4. 게시하지 않는 장치별·실행 자료

- 실제 `config_local.py`와 보드별 센서 포트·수신 주소.
- 토큰·비밀번호·환경변수 파일과 원격 인증 자료.
- 가상환경·빌드 결과·원시 센서 파일·실행 로그·임시 브라우저 프로필·화면 검증 스크립트.

설정 예시를 문서에 적는 것과 실제 장치 설정 파일을 게시하는 것은 다르다.

## 5. 아직 적용 코드가 없는 작업

랜선 직결·고정 IP 전환은 요청을 받은 상태다. 양쪽 인터페이스와 원격 접속 경로 결과를 아직 받지 않았다.
계획은 젯슨 192.168.10.1/24, Pi 192.168.10.2/24이며 OS 프로필에 적용하지 않았다.
따라서 고정 IP 전환이 완료된 코드·설정을 올렸다고 기록하지 않는다.

## 6. 검증 범위

문서의 로컬 링크·근거 이미지·26개 항목과 HTML 펼치기/접기·목차 이동·작은 화면을 확인했다.
진단 도구는 센서를 열지 않는 `--help`와 통계 검사로 검증한다.
격리된 게시 작업공간에서 전체 회귀 검사 163개·ROS 패키지 검사 4개가 통과했다. 진단 도구 --help도 센서를 열지 않고 통과했다. GitHub 검사 결과는 이번 PR 검증 기록을 확인한다.
게시 검사는 유선 연결·장시간 운용·재부팅·안전 기능의 실기 성공을 대신하지 않는다.
