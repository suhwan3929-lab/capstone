# 재시작 복구와 3D 수신 상태

2026-11-04. PC 검증 기준이며 실제 Pi·Jetson 적용은 사용자의 요청으로 미룬다.

## 재시작 복구

감시 프로그램의 상태 송신기와 Jetson 거리 브리지는 실행할 때마다 새 UUID 세션을 만든다.
같은 세션에서는 증가한 순번만 받고, 새 세션은 순번이 1이어도 즉시 받는다.
최근 종료 세션 64개를 기억해 이전 실행의 지연 패킷이 현재 상태를 덮지 못하게 한다.
잘못된 상태 패킷은 순번이나 수신 시각을 갱신하지 않는다.
JSON 스키마 버전은 1을 유지하고 선택 필드 `session`만 추가해 기존 수신기와 호환한다.

세션 필드가 없는 구형 송신기는 링크가 신선한 동안 역순 패킷을 버린다.
마지막 정상 상태로부터 GUI 상태는 2초, 거리 입력은 0.5초가 지나면 낮아진 순번을 다시 받는다.
같은 순번의 중복은 이 시간을 늘리지 않는다. 구형 패킷에는 실행 식별자가 없어 재시작과
지연 도착을 완전히 구분할 수 없으므로 두 송신기를 업데이트해야 한다.
식별된 송신기를 받은 뒤에는 세션 없는 패킷으로 돌아가지 않는다.
구형 송신기로 롤백하는 경우 수신기(GUI 또는 Pi 안전 감시)도 재시작한다.

## 3D 네트워크 재연결

Pi의 유효한 로컬 IPv4에 바인딩하다 실패하거나 수신 소켓이 끊기면 1초마다 다시 연결한다.
연결 오류가 발생하면 이전 점과 조립 중 프레임을 지운다. 재연결 뒤 새 완성 프레임만 표시한다.
창 종료 시 대기를 즉시 취소하므로 종료한 GUI가 포트를 다시 점유하지 않는다.
일반적인 데이터 중단은 기존처럼 완성 프레임이 0.5초 동안 없으면 점을 지운다.

잘못된 IPv4·포트·`0.0.0.0`은 자동 재시도 대상이 아니다. 설정을 고치고 GUI를 재시작한다.
기본 주소 `127.0.0.1`은 PC 로컬 시험용이며, 실기는 `config_local.py`에 Pi의 현재 유선 IP를
`UDP_PREVIEW_BIND`로 지정한다. OS의 고정 IP나 유선망 설정은 변경하지 않는다.

## 화면에서 구분하는 상태

- `거리 정상/주의/위험`, `거리 센서 오류`, `거리 링크 끊김`: 기존 거리 감시 경로의 상태다.
- `3D 수신 중`, `3D 유효점 없음`, `3D 수신 대기/중단`, `3D 연결 확인`: 표시 전용 경로의 상태다.
- 거리·전도 감시가 정상이지만 그림이 중단되면 상단에 예를 들어
  `감시 정상 · 3D 오른쪽 중단`을 노란색으로 표시한다.
- 거리 위험이나 센서 오류가 있으면 기존 위험/오류 표시를 유지한다.
  점군 수신 정상은 거리 경고를 지우지 않으며, 3D 중단을 안전 판정 입력으로 사용하지 않는다.
- PC USB 도구는 거리 판정을 실행하지 않는다. 기존 3D 수신 배지를 유지하고 중복 배지는 숨긴다.

화면 선택 도구줄이나 거리 숫자 행을 다시 추가하지 않는다. 정면 보기, 확대 1/5/10cm,
고정 눈금과 최대 9,600 유효점 표시는 유지한다.

## 적용과 확인

[장치별 적용 안내](deploy_gui_channels.md)에 따라 Pi를 먼저 업데이트하고 Jetson 패키지를 재빌드한다.
Pi에는 새 공통 모듈 `stream_order.py`도 함께 반영하며 GUI와 안전 감시를 모두 재시작한다.
Jetson은 거리 브리지도 업데이트해 세션 식별자를 전송하도록 한다.

점검 시 감시 프로그램과 Jetson을 각각 재시작해 순번이 작아져도 현재 상태가 복구되는지 확인한다.
GUI 시작 전에 유선 인터페이스를 준비하지 않은 경우, 주소가 준비된 뒤 GUI를 다시 열지 않아도
3D가 들어오는지 확인한다. 3D 표시만 중단했을 때 기존 거리 경고·전도 감시가 계속되는지도 확인한다.
실제 보드 재시작 동안 해당 감시 입력이 일시 중단되므로 보행기를 사용하지 않는 점검 시간에 진행한다.
