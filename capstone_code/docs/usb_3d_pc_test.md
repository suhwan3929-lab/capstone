# Windows PC에서 두 USB 라이다로 실제 GUI 시험

작성일: 2026-11-04. 7인치 1024×600 가로 GUI 적용과 PC USB 표시 시험용 안내다.

## 바로 실행

현재 PC 전용 환경을 `capstone_code/.venv`에 준비했다. 상위 폴더의
`START_PC_USB_3D.cmd`를 실행하면 COM4를 USB 1, COM5를 USB 2로 표시한다.
이 이름은 물리적인 보행기 좌우를 확인한 결과가 아니다.

다른 포트가 잡히면 상위 프로젝트 폴더의 PowerShell에서 확인하고 지정한다.

```powershell
.\capstone_code\.venv\Scripts\python.exe .\capstone_code\tools\usb_lidar_3d.py --list
.\capstone_code\.venv\Scripts\python.exe .\capstone_code\tools\usb_lidar_3d.py --left COM4 --right COM5
```

위 COM4·COM5는 이번 PC에서 실제 확인한 포트이며 다른 PC의 기본값이 아니다.
한 포트에 두 프로그램을 동시에 연결하지 않는다. 종료하면 이 도구가 시작한 측정을
정지하고 포트를 닫는다. 이미 실행 중인 시험 창을 닫은 뒤 다시 실행한다.

## 무엇을 시험하는가

- 두 USB 장치의 3D 프레임을 별도 스레드로 수신하고 제조사 체크섬을 검증한다.
- 160×60 깊이값을 제조사 렌즈 테이블로 센서 기준 XYZ로 복원한다.
- 기존 GUI의 좌우 점군 표시, 정면/사선/위/옆 시점과 상세 보기를 확인한다.
- 마지막 유효 표시 프레임에서 0.5초가 지나면 해당 점군을 지운다.
- 한쪽 중단이 다른 쪽 점군을 지우지 않는지 확인한다.

**이 도구에서는 안전 감시, 거리 판정, GPS/IMU, SOS, 보호자 알림을 실행하지 않는다.**
상단의 `USB 3D GUI 시험 · 안전 감시 미실행` 문구와 화면 선택 버튼 줄은 숨기고 제목·시계·수신 프레임 수를 둔다.
제목 아래에는 `화면 확대` 선택만 둔다. `1cm · 5cm · 10cm`는 화면 한 칸의 실제 거리이며 기본은 10cm다.
5cm는 기존 화면 대비 2배, 1cm는 10배 확대다. 양쪽 화면이 함께 바뀌고 데이터나 색 기준은 바뀌지 않는다.
오른쪽 시계는 별도 영역에 30pt 굵은 흰색 숫자로 표시한다.
시간은 8자리 고정 폭이며 수신 프레임 수는 그 아래 상태 줄에 표시한다.
기능 비활성 상태는 하단 안내와 SOS 버튼에 계속 표시한다. 실제 감시 기능을 켠 변경은 아니다.
LiDAR 카드 하단의 장애물 거리·`판정 미실행` 행과 색상 설명은 숨겨 3D 측정 영역을 확장했다.
실제 점군 입력을 표시하지만, 센서 정확도나 보행기 안전 성능을 검증한 것은 아니다.

USB 표시는 원본 160×60의 9,600픽셀 중 0.05~2.0m 유효 점 전체 선택이 기본이다.
오류 코드와 범위 밖의 값은 그리지 않는다. 기존 고정 격자 2,400점 축약 코드는 유지하되
사용자 요청에 따라 점군 선택 버튼은 노출하지 않는다. 전체 점 선택은 매 시간 프레임의 저장/재생 기능은 아니다.
실시간 변환은 계속 최대 10Hz이고 화면은 최신 프레임을 사용하므로 모든 수신 프레임이 그려지지는 않는다.
Jetson→Pi도 v2 분할 전송으로 최대 9,600 유효점을 보낸다. [장치 업데이트 안내](deploy_gui_channels.md)를 따른다.
2m 밖이나 유효하지 않은 측정값은 그림에서 제외된다. 점이 적다고 즉시 고장으로 판단하지 않는다.

점군 확인은 정면 3D로 고정한다. 센서에서 전방을 보는 직교 투영이다.
네 시점 모두 센서에서 점까지의 실제 3차원 거리 색을 사용한다.
고정 색상표는 10cm 파랑, 20cm 청록, 35cm 초록, 60cm 노랑, 1m 주황, 2m 분홍으로 보간한다.
가까운 구간에 더 많은 색 변화를 주며 프레임마다 색 범위를 자동으로 바꾸지 않는다. 위험 등급 색은 아니다.
점 지름은 2px이며 3축 화살표와 센서 원점 모형은 제거했다.
동일한 창 크기·시점·선택 눈금에서는 화면 중심과 배율을 고정하고 자동 확대·축소하지 않는다.
기존 0.5m 눈금 막대와 격자의 화면 길이는 유지하고 기본 배율을 5배로 높였다.
2m는 센서에서 측정점까지의 수신 거리 제한이며 화면의 가로·세로 길이가 아니다.
확대한 화면 경계 밖의 점은 그리지 않지만, 0.05~2.0m 수신 데이터 필터는 그대로다.
현재 기본 화면은 전체 점군 선택 상태의 10cm 확대이며 화면 밖의 점이 잘릴 수 있다.
1cm·5cm 선택으로 확대할수록 보이는 범위는 좁아진다. 모든 점이 화면 밖이면 그 상태를 문구로 표시한다.
전체 범위·확대 전환 코드는 유지하지만 해당 버튼 줄은 숨겼다.
각 그림 위 `화면 N/M점`은 화면 안에 그린 점 수/선택된 점 수다. 같은 픽셀의 점은 겹쳐 보일 수 있다.
센서 자체의 움직임과 측정 잡음은 그대로 보인다. IMU 자세 보정이나 지도 고정 기능은 아니다.

## 제조사 프로토콜과 실행 모드

이 도구는 CygLiDAR D2 SDK의 깊이형 `0x08` 및 깊이+진폭형 `0x88` 패킷을 해석한다.
SDK 출처와 렌즈 데이터 라이선스는 [NOTICE](../third_party/cyglidar_d2/NOTICE.md)에 기록했다.
기본 통신 속도는 3,000,000bps다. 단순 시작 명령만으로 첫 시험에서는 프레임이 나오지 않았고,
장치 정보 요청 후 대기, 거리형 3D 선택, 측정 시작의 SDK 순서를 적용한 뒤 수신됐다.
종료 시 측정 정지 명령을 보낸다. 통신 속도 저장이나 장치 ID 명령은 보내지 않는다.
기본 실행과 `START_PC_USB_3D.cmd`는 USB1 채널 0, USB2 채널 1을 요청한다.

### 기본 주파수 채널과 변경 옵션

```powershell
.\capstone_code\.venv\Scripts\python.exe -u .\capstone_code\tools\usb_lidar_3d.py --left COM4 --right COM5 --left-channel 0 --right-channel 1
```

USB1(COM4)은 채널 0, USB2(COM5)는 채널 1 설정 명령을 보낸다. 지정 범위는 0~15다.
제조사 SDK 순서에 맞춰 3D 측정 시작 직후 `0x0F` 명령을 보내며 재연결 때도 다시 보낸다.
채널 옵션을 생략해도 기본값 0/1을 사용한다. `--keep-channels`는 측정 시작/정지는 수행하되 채널 명령을 생략한다.
`--passive`는 시작/정지와 채널 명령을 모두 생략한다. 이 두 모드와 명시적 채널 옵션의 조합은 거절한다.

카드의 `CH0`·`CH1`은 프로그램이 요청한 채널이다. 로그의 `requested_channel`은 요청값,
`channel_command_sent`는 명령 전체가 직렬 포트에 전송된 채널이다. 부분 전송은 오류로 처리한다.
장치의 현재 채널을 읽어오는 응답이나 광학 주파수 측정으로 확인한 값은 아니다.
채널 기본값은 실행 프로그램에 적용했으며 장치 ROM 저장 명령은 보내지 않는다.
제조사 문서에서 채널의 전원 재인가 후 유지 여부는 확인되지 않았고, 종료 시 이전 채널 자동 복원 기능은 없다.
사용자는 채널 0/1 분리 후 간섭 감소를 확인했다고 보고했다. 이는 사용자 관찰이며 광학 주파수 계측이나 정량 성능 인증은 아니다.

다른 프로그램에서 이미 측정을 시작한 경우 명령을 보내지 않고 읽기만 할 수도 있다.

```powershell
.\capstone_code\.venv\Scripts\python.exe .\capstone_code\tools\usb_lidar_3d.py --left COM4 --right COM5 --passive
```

`--passive`에서는 시작/정지 명령도 보내지 않는다. 센서가 대기 상태이면 데이터가 없을 수 있다.
`--baud 921600`은 PC 포트의 읽기 속도만 선택하며 센서의 저장된 baud를 바꾸지 않는다.
다른 모델이나 펌웨어는 실제 패킷 길이·형식과 일치하는지 별도로 확인해야 한다.

## 실제 확인 범위

2026-11-04 이 PC에서 다음을 확인했다.

- Prolific PL2303GC USB Serial 장치 두 대, COM4·COM5, USB VID:PID `067B:23A3`.
- 두 포트가 3Mbps에서 제조사 장치 정보 응답을 보냈고 체크섬을 통과했다.
- 30초 제한 시험에서 포트별 유효 3D 프레임 415개, 표시 갱신 208회,
  체크섬 오류 0개, 잘못된 3D 페이로드 0개를 확인했다.
- 실제 Tk 창에서 양쪽 `3D 수신 중`과 측정점을 확인했다. 모의 점군이 아니다.
- 후속 3분 제한 시험에서는 COM4·COM5 각각 유효 프레임 2,688개, 표시 갱신 1,344회,
  체크섬 오류와 잘못된 페이로드 0개를 확인했다. 사용자가 두 장치 모두 D2임을 확인했다.
- 물리 좌우, 거리 정확도, 장시간 안정성, 실제 Pi/Jetson 동작은 이 결과에 포함하지 않는다.

같은 날 정면 기본 보기, 2px 점, 고정 투영 눈금, 3축 제거를 추가했다.
점군이 바뀌어도 공통 측정점의 화면 좌표와 거리 눈금이 유지되는 것을 네 시점에서 검사했다.
전체 회귀 테스트 153개를 통과했고 1024×600의 정면 버튼·SOS·상세·사고 조치 버튼 배치를 검사했다.
고밀도 USB 점군은 Pillow가 있으면 측정점만 투명 이미지 한 장으로 그린다.
이 PC의 두 센서 각 2,400점 모의 부하에서 10회 평균 그리기 시간은 약 79ms였다.
실제 Pi 성능이나 고정 프레임률 보장은 아니다. Pillow가 없으면 개별 점 그리기로 돌아간다.
후속 색상표 최적화와 전체 점군 추가 뒤에는 두 센서 각 9,600점 모의 입력의 전체 보기에서
10회 평균 약 34ms를 확인했다. 전체 회귀 테스트 157개와 1024×600 버튼 배치를 확인했다.
실제 COM4·COM5에서도 전체 점군 켬 전환을 확인했다. 한 수신 시점에서
각각 범위 안 유효점 2,651/2,445개가 동일한 수의 점군으로 변환됐고 체크섬·페이로드 오류는 0개였다.
실제 전체 보기의 그림 위에서도 화면 점 수와 선택된 점 수가 일치했다. 점 개수는 장면에 따라 변한다.

## 다음 현장 확인

### 2026-11-04 정지 상태의 USB1 변동 확인

`tools/diagnose_usb_lidar_3d.py`로 동시 → USB1 단독 → 동시 순서로 각 6초를 수집했다.
각 포트는 GUI와 같은 독립 스레드로 읽고, 단계마다 시작 후 2초 이상은 제외했다.
USB1 유효 프레임은 91/90/91개이며 세 구간 모두 체크섬·페이로드 오류는 0개였다.
중앙 10×20픽셀에서 같은 픽셀의 연속 유효 거리값 차이 중앙값은 11/10/10mm,
95백분위는 30/27/29mm였다. 이 조건에서 USB2를 꺼도 변동이 크게 줄지 않았다.
두 장치 간섭이 주요 원인이라고 단정할 근거는 약하며 다른 배치의 간섭을 배제한 결과는 아니다.
표시 배율은 5배이고 측정 잡음에 대한 시간 필터는 적용하지 않아 이 변동이 그대로 보인다.

근거 파일은 `logs/usb_jitter_20261104_threaded.json` 및 같은 이름의 원본 깊이 `.npz`다.
이전 `usb_jitter_20261104.json`, `usb_jitter_20261104_repeat.json`은 단독 구간의
직렬 수집 지연과 체크섬 오류로 비교에 사용할 수 없다. 그 문제는 진단 도구에 있었고,
기존 GUI는 원래 포트별 독립 스레드를 사용한다.
측정 당시 USB1 중앙 거리 중앙값은 258/283/275mm로, 앞서 사용자가 말한 약 100mm와
조건이 같은지 확인해야 한다. 이를 근거로 거리 정확도나 특정 반사 문제를 단정하지 않는다.

### 거리·연결 확인 순서

1. 센서 정면에 판을 두고 0.5m·1.0m·1.5m에서 점군 위치 변화와 수신 상태를 본다.
2. 물체를 움직여 실제 점군이 따라 변하는지 확인한다.
3. 한쪽 USB를 분리해 0.5초 뒤 해당 점군만 지워지는지 확인하고 복구한다.
4. 각 센서 단독과 두 대 동시 수신을 비교한다. 동시 사용의 간섭이나 거리 정확도는 실물 기준으로 확인한다.

실제 장치 연결 전에는 모의 화면으로도 배치를 확인할 수 있다.

```powershell
.\capstone_code\.venv\Scripts\python.exe .\capstone_code\tools\preview_lidar_3d.py --dashboard --size 1024x600
```

## 다른 PC에 준비

프로젝트 전용 Python 3.12 환경을 만들고 `numpy`, `pyserial`, `pillow`, `requests`를 설치한다.
tkinter는 Python 설치에 포함되어 있어야 한다. 이 PC에서는 PyPI 연결 지연으로,
동일한 Python 3.12용 기존 설치 패키지와 공식 pyserial v3.5 소스를 전용 환경에 복사해 준비했다.
센서 USB 드라이버는 Windows 장치 관리자에서 정상 COM 포트가 잡히는지 별도로 확인한다.
