# `tipover_monitor.py`

> **한 줄:** 보행기 전도 판정 FSM. **이 시스템의 심장.**
> **계층:** 판정 (안전 필수) | **의존:** `config`, `notifier`, `buttons`, `schema`, `sensors.*_source`, `states`

---

## 무엇을 하는가

IMU 샘플을 100 Hz로 받아 상태 기계를 돌리고, 전도가 확정되면 `notifier` 로 신고한다.

```
평상시 ──충격 ≥ IMPACT_THRESHOLD_G──> 충격 감지
                                      │
              ┌───[기울기 < 60°]──────┤ STABILIZE_TIME 경과
              ↓                       ↓ [기울기 ≥ 60°]
           평상시 (해제)          움직임 분석중
        (방지턱·내려놓기)             │
                                      ├─[의미 있는 움직임 2회]→ 평상시 (해제)
                                      ├─[자세 정상 복귀]────→ 평상시 (해제)
                                      ↓ CHECK_TIME 경과
                                   응답 대기
                                      ├─["아니오"]──────────→ 평상시 (해제)
                                      ↓ ["예" 또는 무응답]
                                   사고 확정 → 신고 완료
```

**SOS 명령은 이 전 과정을 건너뛰고 즉시 확정으로 간다.**

## 왜 존재하는가

리팩터링 전에는 판정 로직이 **GUI의 `_refresh()` 안**에 있었다.
tkinter가 지도 타일을 받다 멈추거나 위젯에서 예외가 나면 **전도 감지가 같이 죽었다.**

이 모듈은 GUI와 완전히 분리되어 있다. `ui.py` 를 죽여도 여기는 계속 돈다.

## 공개 인터페이스

```python
class TipoverMonitor:
    def __init__(self, log_callback=None, clock=time.time)
    def start(self)                    # 100 Hz 판정 스레드 기동
    def stop(self)
    def submit(self, cmd: str)         # 사용자 명령 (스레드 안전)
    def snapshot(self)                 # → (state, ask_deadline, alert_sent)
    def step(self, imu, gps)           # 한 틱 직접 실행 (오프라인 재생용)
```

## 설계 포인트

### 시계 주입 (`clock` 인자)

`tools/replay.py` 가 **가상 시계**를 넣어 기록된 CSV를 실시간보다 수백 배 빠르게 재생한다.
이 덕분에 **재생과 실주행이 완전히 같은 판정 코드**를 쓴다.
별도의 오프라인 구현을 만들면 "재생에서는 되는데 실기에서 안 되는" 문제가 생긴다.

### 기울기 관문 (가장 중요한 오탐 방지 조건)

충격만으로 확정하지 않는다. `STABILIZE_TIME` 후 **기울기 ≥ `TIPOVER_TILT_DEG`** 여야
다음 단계로 간다. 이 조건이 없으면 **횡단보도에서 턱을 넘고 5초 서 있을 때
보호자에게 사고 신고가 간다.**

### 움직임 판정의 시간 간격

`MOVE_MIN_INTERVAL` 이 없으면 100 Hz에서 **연속된 노이즈 2샘플로 실제 전도가 취소**된다.
미탐(전도를 놓침)은 오탐보다 위험하므로 이 조건은 필수다.
기준점(`_base`)도 한 샘플이 아니라 `BASELINE_AVG_SEC` 구간 평균을 쓴다.

### 명령 유효기간 (`CMD_TTL = 3.0`)

명령을 매 틱 무조건 비우면, **상태 전이와 같은 틱에 도착한 명령이 그대로 버려진다.**
"아니오(취소)"가 이렇게 유실되면 오신고가 그대로 나간다.
그래서 3초 유효기간을 두고, 판정 중인 **어느 단계에서든** 취소를 받아들인다.

### 재무장 쿨다운 (`REARM_COOLDOWN`)

해제 직후에도 보행기가 여전히 기울어 있을 수 있다(바닥에 눕혀둔 상태).
이때 작은 충격 하나로 즉시 재확정되어 **같은 상황을 반복 통보**하는 문제가 있었다.

## 고칠 때 주의

- ⚠ **`step()` 안에서 블로킹 I/O를 하지 말 것.** 100 Hz 루프다.
  웹훅 전송은 `notifier` 가 별도 스레드에서 처리한다.
- ⚠ **`time.time()` 을 직접 부르지 말고 `self._now()` 를 쓸 것.**
  직접 부르면 `tools/replay.py` 의 가상 시계가 무력화된다.
- ⚠ **IMU가 `valid=False` 면 상태를 진행시키지 않는다.** 죽은 센서로
  엉뚱한 확정이 나가는 것을 막는 안전장치다.
- ⚠ 상태를 추가하면 `states.TIPOVER_DISPLAY` 와 `alerting.tipover_state_to_level()`
  양쪽에 매핑을 추가해야 한다.
- **이 파일을 고쳤으면 반드시 `python tests/run_all.py` 를 돌릴 것.**
  12개 회귀 테스트가 위 설계 포인트를 각각 지키고 있다.
