# 일반 사용자용 GUI 구성 계획

작성일: 2026-11-04. 3D 중심 가로 배치를 실제 `ui.py`에 반영했다.
상위 작업 폴더의 소스 기준이며 GitHub 게시·실제 Pi 배포는 별도다.

## 공통 구성

기본 화면에서 현재 상황, 좌우 장애물 거리, 보행기 전도 감시 상태, 긴급 호출을 바로 확인한다.
사용 목적은 수신한 3D 점군을 그대로 확인하는 것이다. 기본 표시는 고정 정면 시점의 3D로 두고,
2D 평면도는 보조 전환으로 제공한다. 배터리와 측위 상태는 간단히 표시하고 GPS 세부 수치·Roll/Pitch·3D 시점 조작·로그는
`센서 상세 보기`로 옮긴다. 상세 화면에서 기본 화면으로 돌아오는 버튼을 항상 제공한다.
상세 화면에서도 SOS 또는 사고 조치 버튼에 바로 접근할 수 있게 한다.

사용자가 확인한 화면은 7인치 1024×600 가로 모니터다.
모형은 이 비율과 좌우 배치를 고정하고, 대화창이 좁아지면 전체를 비례 축소한다.
Pi 구현은 실제 픽셀 크기와 터치 환경에서 다시 확인해야 한다.
아래 수치는 설계 제안이며 검증된 사용자 실험 기준은 아니다.

- 실제 구현은 Tk의 글꼴·화면 배율에 맞춰 버튼 공간을 확보하며, PC에서 실제 크기와 부모 영역 포함 여부를 검사한다.
- 네 안 모두 기본 화면의 같은 하단 위치에 SOS를 두어 찾는 위치를 일정하게 한다.
- 이상 상태는 색상과 문구를 함께 사용한다. 정상, 거리 주의, 거리 위험, 수신 중단을 구분한다.
- 기존 표시 임계값 0.8m 이하 위험, 1.5m 이하 주의를 유지한다. 화면 검토 때문에 판정 임계값을 바꾸지 않는다.
- 연결이 끊기면 이전 거리·현재 위치·정상 상태를 지운다. 알 수 없는 배터리는 퍼센트를 표시하지 않는다.
- SOS 요청과 Discord 서버 접수, 보호자 열람은 구분한다. 서버 접수를 보호자 수신/열람 완료로 표시하지 않는다.
- 좌우 점군은 각 센서 좌표로 분리한다. 장착 위치·방향 보정 없이 하나의 보행기 지도처럼 합치지 않는다.
- 장애물이 있는 방향을 표시할 뿐, 검증되지 않은 회피 방향이나 안전 이동 경로를 안내하지 않는다.
- 수신 중단이어도 GUI가 안전 판정을 대신하지 않는다. 기존 독립 감시 프로세스를 유지한다.

## 네 가지 대안

### 3D 균형형, 추천

상단 현재 상황, 중앙 좌우 거리와 3D 점군, 하단 전도·측위 요약과 SOS를 둔다.
기존 좌우 카드 구조를 유지하면서 상세 조작과 로그를 숨기는 방향이다.
숫자와 공간 정보를 함께 남겨 현재 GUI에서의 전환 범위가 비교적 작다.
표시 정보가 너무 많아지지 않도록 기본 화면의 센서 지표를 제한한다.

### 큰글씨형

가장 가까운 장애물 거리와 해당 센서 방향을 중앙에 크게 표시한다.
좌우 개별 거리는 옆의 두 보조 영역에 남기고 공간 윤곽은 상세 화면에서 확인한다.
숫자 판독이 쉽지만 장애물의 대략적인 형태를 기본 화면에서 볼 수 없는 것이 단점이다.
센서 하나가 끊기면 정상인 반대쪽 센서의 거리만으로 전체가 정상이라고 표시하지 않는다.

### 3D 점군 중심형

좌우 개별 센서의 3D 점군을 넓게 표시하고 거리 숫자는 각 그림 위에 둔다.
기존 요청인 ‘그림으로 대략 형태 보기’를 가장 강조한다.
숫자 중심 안보다 읽고 해석할 내용이 많아 사용자 확인이 필요하다.
점군은 모의 XYZ 데이터이며 인식 결과나 누적 지도, 보행기 전체 좌표계가 아니다.
색상은 센서에서 측정점까지의 거리이며 위험 등급과 구분한다. 바닥/중력 기준 보정 전이다.

Pi/Jetson UDP 3D 표시 경로는 센서별 최대 192점, 0.05~2.0m 범위, 최대 10Hz로 축약한다.
Windows 직접 USB 시험 경로는 고정 픽셀 격자의 최대 2,400점과 최대 9,600 유효 점 전체 선택을 전환한다.
점 지름은 2px이며 3축 모형은 제거했다. 점군 변화에 따라 화면 중심·배율·10cm 눈금이 바뀌지 않는다.
따라서 원본 PointCloud2 전체를 그대로 보내는 경로와는 다르다. 원본 전체 표시가 필요하면
전송량과 Pi 렌더링 부하를 별도로 측정한 뒤 이 표시 경로를 재설계해야 한다.

### 상태 집중형

중앙에 ‘오른쪽 장애물 주의’ 같은 상황 문장을 크게 표시한다.
좌우 거리는 하단 두 영역에 유지하고, 점군과 센서 수치는 상세 화면으로 옮긴다.
현재 상황을 빨리 읽기 쉽지만 개별 장애물 형태와 수치의 비중은 작아진다.
의학적 상태나 사용자의 낙상을 단정하지 않고 측정 가능한 보행기 전도 상태만 표시한다.

## 상태별 검토와 구현 순서

1. 네 안에서 같은 모의 데이터를 사용해 배치 차이를 비교한다.
2. 평상시·거리 주의·위험·감시 연결 끊김·사고 알림 처리 예시를 확인한다.
3. 기본 3D 화면과 상세 화면을 Tkinter로 구현했다. 위험 강조는 SOS를 가리지 않는 배너 테두리 점멸로 바꿨다.
4. 좌우 한쪽 센서 단절, GPS 무효, 포트 충돌, 긴 문구, 신고 전송 실패까지 기존 테스트로 확인한다.
5. Pi에서 1024×600·1280×720, 터치 목표 크기, SOS·감시 재개 버튼 노출을 확인한다.
6. 실제 SOS 시험은 합의한 시험 채널과 절차에서 별도로 수행한다.

화면 모형의 SOS와 감시 재개는 예시 상태만 바꾸며 네트워크 요청이나 실제 신고를 하지 않는다.
실제 USB 라이다의 PC 시험은 [USB GUI 시험 안내](usb_3d_pc_test.md)를 따른다.
