# `console.py`

> **한 줄:** 윈도우 콘솔에서 이모지 한 글자 때문에 프로세스가 죽는 것을 막는 안전장치.
> **계층:** 기반 | **의존:** 없음

---

## 무엇을 하는가

- `setup()` — `sys.stdout` / `sys.stderr` 를 UTF-8(`errors="replace"`)로 재설정
- `safe_print()` — 어떤 경우에도 예외를 밖으로 내보내지 않는 `print`

## 왜 존재하는가 — 실제 크래시에서 나왔다

윈도우 콘솔의 기본 인코딩은 **cp949** 다. 로그 메시지에 들어간 `✅ ⚠ ✗ 🆘` 같은 문자를
출력하지 못하고 **`UnicodeEncodeError` 로 프로세스를 죽인다.**

이 문제는 개발 중 실제로 두 번 터졌다.

1. `safety_monitor.py` 가 자체 진단 메시지의 `⚠` 때문에 죽을 수 있었다.
   → **안전 필수 프로세스가 로그 한 줄 때문에 죽는 것은 용납할 수 없다.**
2. `tools/replay.py` 가 결과 표의 `✗` 를 출력하다 죽었다.

## 사용법

모든 진입점(`safety_monitor.py`, `ui.py`, `tools/*`, `tests/run_all.py`)에서
**맨 위에 한 번** 호출한다.

```python
import console
console.setup()
```

## 고칠 때 주의

- **새 진입점 스크립트를 만들면 `console.setup()` 을 반드시 넣을 것.**
  안 넣으면 그 스크립트만 윈도우에서 간헐적으로 죽는다.
- `setup()` 은 예외를 삼킨다. `reconfigure()` 가 없는 환경(구버전 파이썬,
  파이프로 리다이렉트된 스트림)에서도 조용히 넘어가야 하기 때문이다.
- 리눅스(Pi)에서는 보통 이미 UTF-8이라 아무 일도 하지 않는다. 해가 없다.
