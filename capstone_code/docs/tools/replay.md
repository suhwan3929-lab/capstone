# `tools/replay.py`

> **한 줄:** 기록된 CSV를 실제 판정 코드에 다시 통과시켜 임계값을 탐색한다.
> **이 프로젝트에서 가장 중요한 분석 도구.**
> **계층:** 분석 도구 | **의존:** `config`, `notifier`(스텁), `schema`, `states`, `tipover_monitor`

---

## 해결하는 문제

`IMPACT_THRESHOLD_G = 2.8`, `TIPOVER_TILT_DEG = 60` 이라는 숫자를 방어해야 한다.
심사에서 **"왜 2.8입니까?"** 를 반드시 묻는다.

그런데 임계값을 바꿀 때마다 실험을 다시 하는 것은 불가능하다.
그래서 **기록해 둔 CSV를 실제 판정 코드에 다시 통과시킨다.**

## 핵심 설계 — 왜 신뢰할 수 있는가

```python
mon = TipoverMonitor(clock=virtual_clock)   # 시간만 가짜, 로직은 진짜
mon.step(imu, gps)
```

**재생과 실주행이 완전히 같은 `tipover_monitor` 코드를 쓴다.**
별도의 오프라인 구현을 만들면 "재생에서는 되는데 실기에서 안 되는" 문제가 생긴다.

가상 시계라 20초짜리 로그가 수십 ms에 끝나고, 수백 개 조합을 한 번에 훑을 수 있다.

## 사용법

```bash
python tools/replay.py logs/tipover_front_20260821.csv -v   # 판정 과정 출력
python tools/replay.py logs/                                # 전체 채점
python tools/replay.py logs/ --sweep                        # 임계값 전수 탐색 ← 보고서용
```

## 양성/음성 분류

파일명 접두사로 자동 분류한다.

- **양성:** `tipover_*` (`tipover_front`, `tipover_side`, `tipover_rear`)
- **음성:** 그 외 전부
- `*_recover` 가 들어가면 **해제되어야 하는 케이스**이므로 음성
- 용어 변경 이전의 `fall_*` 로그도 양성으로 인식 (하위 호환)

## `--sweep` 출력

```
  순위    충격(g)     기울기(°)    탐지    미탐    오탐    정상     벌점
   1     3.80         30     1     0     0     5      0
...
✅ 완전 분리 구간: 충격 3.80~4.60 g, 기울기 30~80°
   여유를 최대로 하려면 구간 중앙값을 쓰세요: 충격 4.20 g, 기울기 55°
```

**이 표와 구간이 그대로 보고서의 임계값 근거 자료가 된다.**

### 벌점 = 미탐×3 + 오탐

**안전 시스템에서 두 오류의 무게는 같지 않다.**
전도를 놓치는 것이 헛울리는 것보다 위험하므로 미탐에 3배 벌점을 준다.

## 고칠 때 주의

- ⚠ **시뮬레이터가 만든 CSV로 임계값을 정하지 말 것.**
  입력이 가정이면 출력도 가정이다 — **순환 논리**다.
  실제로 한 번 그런 결과를 낸 적이 있다. `설계값_근거.md` §0 참조.
- ⚠ **import 시점에 `notifier` 함수를 스텁으로 갈아끼운다.**
  재생 중 실제 알림이 나가면 안 되기 때문. 이 순서를 바꾸지 말 것.
- ⚠ `--sweep` 은 `config` 값을 임시로 바꿨다가 복원한다. 중간에 예외가 나면
  복원되지 않을 수 있으므로, 이 함수 안에서 예외를 던지지 말 것.
- CSV 열 이름이 바뀌면 `replay_file()` 의 `row[...]` 접근도 고쳐야 한다.
