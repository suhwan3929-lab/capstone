## 1. 기본 구조와 실행

- Raspberry Pi는 Python 안전 감시, IMU/GPS, 현장 경보, 보호자 알림과 대시보드를 담당한다.
- Jetson은 ROS 2로 좌우 LiDAR를 처리해 Pi로 전달한다.
- 안전 거리·상태는 UDP 9100, Pi 내부 상태/명령은 9101/9102를 사용한다.
  작업 원본의 LiDAR 3D 표시 전용 경로는 9103이며 안전 판단과 분리한다.
- `run_dev.py`는 `safety_monitor.py`와 `ui.py`를 함께 시작한다.

`capstone_code` 폴더에서 준비된 가상환경의 Python으로 시작한다.

```bash
python run_dev.py --sim --scenario normal_walk --no-alert
```

일반 SSH처럼 GUI가 없는 경우 `--no-ui`를 추가한다. 종료는 Ctrl+C다.
시뮬레이션 값은 실제 센서 측정이 아니다. `--no-alert`는 현장 경보 출력을 끄지만
Discord 전송을 막지 않는다. 사고 시나리오와 SOS 시험은 수신 대상 및 기존 미전송 기록을 먼저 확인한다.
설치 절차는 [소프트웨어 README](../README.md)를 따른다.

## 2. Ubuntu 원격접속에서 확인한 내용

- PC 유선 LAN과 Pi Wi-Fi는 같은 공유기에서 서로 접근 가능하면 사용할 수 있다.
- Pi는 Ubuntu다. Raspberry Pi OS용 `raspi-config`와 Connect 절차를 Ubuntu SSH 설치로 정정했다.
- `ssh yu@192.168.0.173`에서 `Connection refused`를 확인했고 OpenSSH 설치·시작을 안내했다.
- 사진에서 `unattended-upgrade` 프로세스 13069가 APT 잠금을 보유한 것을 확인했다.
  잠금 파일 삭제나 임의 강제 종료 대신 진행 로그를 확인하도록 했다.
- 이 대화의 해당 오류에 대한 후속 설치 로그·SSH 재접속 결과는 아직 없다.
  다른 날짜의 사용자 확인 기록으로 이 오류의 해결 여부를 대신 판정하지 않는다.

`yu`, 과거 IP, Python/설치 경로는 장치에서 다시 확인한다.
상세 명령과 APT 잠금 점검은 [Ubuntu 원격접속](remote_access.md)에 있다.

4. 자동 실행 설치 후 재부팅·서비스·GUI·센서 갱신과 격리 시험.

위치 접근 실패 또는 120초보다 오래된 측정이면 전송을 중단하고 IP 위치로 대체하지 않는다.

정확도 수치는 위치 서비스의 보고값이며 실제 GPS 정밀도를 증명하지 않는다.

자동 실행 설치기 `systemd/install_autostart.py`와

설치기는 앱 소스·ROS 패키지나 비밀 설정을 배포/갱신하지 않는다.

## 5. Pi–Jetson 유선 LAN 전환 계획

로컬의 `라즈베리파이_젯슨_유선랜_전환_매뉴얼.md`에 다음 구성을 작성했다.

- LAN 케이블 직결: Pi `192.168.10.2/24`, Jetson `192.168.10.1/24`.
- 유선 게이트웨이/DNS는 비우고 `ipv4.never-default yes`로 인터넷 기본 경로를 바꾸지 않는다.
- Discord·NTRIP·지도·PC 원격접속용 Wi-Fi/LTE는 유지한다. 직결 LAN은 인터넷을 제공하지 않는다.
- 먼저 NetworkManager가 해당 유선 장치를 관리하는지와 주소 대역 중복을 확인한다.
  장치가 unmanaged거나 다른 네트워크 관리자를 쓰면 해당 명령을 바로 적용하지 않는다.
- Jetson 전송 대상 `pi_host`를 Pi의 유선 주소로 변경한다.
  후속 코드의 3D 사용 시 UDP 9103도 별도로 확인한다.
- 양방향 ping뿐 아니라 `ip route get`의 유선 경로, UDP 9100/9103 실제 수신,
  좌우 센서 값 갱신, 랜선 단절/복구, 재부팅, 30분 운용을 검사한다.

이것은 작성된 전환 절차다. 실제 보드의 IP 변경·통신·재부팅 시험을 수행한 기록은 아니다.
설정 변경/재시작은 사람이 사용하지 않는 정지 상태에서 진행한다.
